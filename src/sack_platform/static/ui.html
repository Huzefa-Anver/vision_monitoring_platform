Upload a labelled dataset

A .zip in YOLO layout: images/ and labels/ (split folders such as train/val inside, optional data.yaml), at the top of the zip or inside one folder. It becomes a new folder datasets/<name>_upload_vNNN; nothing existing is changed and it is not merged into any training set. Every image is checked against the benchmark (same file content, or a reserved eval day in the name) and the result is shown on the dataset.

Record from RTSP

Record one or more cameras at the same time, e.g. while a truck is being loaded. Add a row per camera, press start, and press stop when you are done — each camera becomes its own video file below. Leave fps empty to keep the camera's own frame rate (no re-encoding, lightest on the server); set it (e.g. 5) to save a smaller file at that rate. Frame size works the same way: "original" keeps the camera resolution; a width resizes every frame (height follows the camera's aspect ratio). Changing fps or size re-encodes on the server's CPU. If a stream drops, the camera reconnects on its own and continues in a new part file.

Which recordings exist

Paste a camera's playback link, for example rtsp://user:pass@host:port/cam/playback?channel=5, and pick a time range. The recorder is asked for video at each step, one time at a time with a short pause. RTSP cannot list recordings, so this is a probe: a gap shorter than the step can be missed. The check stops at the first login failure, so a wrong password cannot lock the account. Check the clock printed on each thumbnail: on some recorders it differs from the requested time, and a request inside a gap may jump to the next recording.

RTSP server ...

Plays saved video files as RTSP camera streams, for testing the counter on known videos. Set each stream below, then press Save and apply: the server picks up the change by itself, a changed stream restarts (its viewers are disconnected) and the others keep playing. Restart server disconnects every viewer. Videos come from (copy new ones there, for example with scp, and press reload videos) and from the recordings made in tab 8 (rename them there; streams follow the new name).
Viewer login
One user name and password for every stream that ticks password on its card; the link and copy button of those streams include it. Streams without the tick can be watched without a password, from the local network only. Anyone who can open this platform page can see the password.
Public address
For streams that tick public on their card (they must also tick password). The router must forward this port (TCP) to 10.1.1.147:8554; this page cannot change the router. A stream without the public tick refuses viewers from outside the local network, even if the router forwards the port.
